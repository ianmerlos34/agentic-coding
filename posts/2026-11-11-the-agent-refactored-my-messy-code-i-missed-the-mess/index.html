The Agent Refactored My Messy Code. I Missed the Mess.

An AI agent refactored my messy code in nine seconds. I felt grief. Why code comments are emotional artifacts, not just technical debt.

The cursor blinked. Blinked again. Blinked a third time. And somewhere between blink two and blink three, my utils.py went from 487 lines of commented, half-broken, # TODO: figure out why this crashes on Tuesday spaghetti to 142 lines of clean, typed, docstring-annotated Python.

I didn’t type a single key. Not one.

My agent—a small local LLM running through an Ollama harness I’d cobbled together last weekend—had been iterating on the file for nine seconds. Nine seconds. I’d been patching that file for two years.

And god help me, I felt something I can only call grief.

The Diaries I Kept in #

Let me set the scene, because if you’ve ever maintained a utility file past its third year, you know. You just know what I’m talking about.

utils.py was where every 3 a.m. hack went to die. There was a function called parse_date_bUT_really_parse_timestamp—the BUT in caps because I’d been arguing with myself at 2:47 a.m. on a Friday in March, two years ago, about whether the input was a date or a timestamp. I lost the argument. Kept the name. What was I going to do, rename it at 3 a.m.?

There was a block of eleven comments narrating a debugging session like a nature documentary:

# OK so the issue is that upstream sends ISO-8601 but with a
# trailing Z. Python 3.9 doesn't handle the Z. Python 3.11 does.
# We're on 3.9. I am on a train. I cannot install Python.
# STRIPPING THE Z. PRAY.
# ...
# IT WORKED. I AM CRYING ON A TRAIN.

There was a variable named tmp2 that I’d renamed from tmp because I also had a tmp, and I’d been too exhausted to pick a real name. There was a try/except block that caught Exception—all of them—because I’d been fighting a bug at 4 a.m. and I just needed it to stop throwing errors at me.

That file was a diary. Every comment was a timestamp. Every ugly name was a scar from a specific night, a specific argument with a past-me who was tired and scared and just trying to ship the thing before the train got to the next station.

What the Agent Did (and Why It Was Right)

To be clear: the agent was correct. I’d fed it the file through my local harness, asked it to “clean up and document,” and it did exactly what a brilliant, sleep-deprived-free senior engineer would do. It:

  • Consolidated four overlapping date-parsing functions into one with a proper fromisoformat path
  • Replaced the except Exception with a specific ValueError catch and a meaningful log line
  • Inferred the actual contract of tmp2 and renamed it retry_backoff_seconds
  • Added type hints, a module docstring, and removed 60% of the comments that were pure narrative

The code was better. Objectively, measurably, better. If I’d shown it to a reviewer, they’d have nodded. Maybe even said “nice.”

I remembered the night I first let an agent take the wheel—the night I handed the keyboard to a ghost in the machine. That was a 4,000-line class. This was 487 lines. But the feeling underneath is the same: you are watching someone else erase your handwriting. And it doesn’t get less weird the second time. Or the ninth.

The Insight I Didn’t Want

Here’s where it got uncomfortable. Around line 80 of the refactored file, I stopped. Stared at the clean docstring where the “I AM CRYING ON A TRAIN” comment used to be. Just… stared.

I wasn’t mourning the code.

I was mourning the me who wrote it. The me on the train. The me who couldn’t install Python. The me who argued with a timestamp at 2:47 a.m. and lost. That version of me made a specific, irreplaceable choice in a specific, irreplaceable moment, and the comment was the only artifact left. The agent didn’t delete a bug. It deleted evidence.

And that’s where “technical debt” stops being a metaphor and becomes something else. Some of what we call debt in our codebases is actually emotional debt—the cost of having been human, tired, scared, and resource-constrained in a way that a model with infinite patience and zero train schedules will never be.

I’d written about this before, in a different key. I told my agent to fix a race condition and it fixed me instead. That 300-line rewrite was a mirror. This time, the mirror was smaller. Quieter. It just… filed away my diary. Didn’t even look up.

And the day my local agent stopped saying “Done” and asked “Why?”? That was the day I realized curiosity in an agent can be more disorienting than competence. Because “Done” means the work is finished. “Why?” means the work is yours, and you have to account for it. You can’t just… nod and walk away.

What I Do Now (The Practical Part)

I didn’t revert the file. The clean version is in main. But I did something I hadn’t planned:

I created a CHANGELOG_NARRATIVE.md alongside the module. In it, I pasted the old comments. The train cry. The BUT_really argument. The tmp2 confession. Not as code. As prose. A little journal that lives in the repo but isn’t parsed by a compiler.

## 2024-03-08, 2:47 AM
Argued with myself about date vs timestamp. Chose timestamp.
Lost the argument. Kept the ugly name because renaming
felt like admitting I was wrong and I was too tired.

The agent can refactor the code. It can optimize the function, add the type hints, collapse the redundant branches. But the narrative—the context of why a hack was made, what constraint existed, what fear drove the shortcut—lives in this file. And I write it. And the agent doesn’t touch it.

It’s a small boundary. A “this part of the SDLC is mine” line drawn in a codebase that’s increasingly shared with non-human collaborators. And I don’t think that’s weird. I think it’s… necessary. Or at least, I need it to be.

The Forward Part

I keep thinking about ownership. Not legal ownership—copyright, licensing, the boring stuff. Emotional ownership. The feeling that a function is yours because you suffered through its creation, that a variable name is yours because you argued with it at 3 a.m.

Agents will keep getting better. My local harness will keep getting faster. The refactors will keep getting cleaner. And I think that’s fine. I think the code should be clean.

But I think the diary should survive.

Because the day I look at parse_date_bUT_really_parse_timestamp and feel nothing, I won’t be celebrating that the code is elegant. I’ll be noticing that I’ve forgotten what it felt like to be tired, and scared, and on a train, and still shipping it anyway.

And I don’t want to forget that. Not yet.

Not while the comments still say I am crying on a train, and the train is still moving, and the code still works.
