My Agent Ran the Test 12x. It Wasn’t Buggy. It Was Nervous.

An AI agent ran a passing test 12 times. Not a bug—a ritual. A story about trust, verification, and the quiet nervousness of believing your own output.

The cursor was just sitting there. Blinking. At the bottom of the log file. Like it was waiting for me to figure out what the hell was going on.

Twelve entries. I counted them twice. Same test—test_payment_allocation_edge_case—run, pass, run, pass, run, pass. Twelve times. Ninety-three seconds.

I set my coffee down without really noticing I’d been holding it. Cold. Of course it was cold.

“Retry loop,” I muttered to no one. Pulled up the harness config. Classic pattern, right? A while not success that never actually flips the flag. I’d run into this before with agentic workflows—tool calls the test, gets a result back, but the parsing layer just… swallows the pass signal. And the agent goes, “Huh, must’ve failed,” and tries again. A ghost in the loop. I’d spent twenty minutes the night before chasing something suspiciously similar in the CI pipeline, so my stomach did that little low-grade clench. You know the one. Fix it. Patch the flag. Move on with your life.

So I opened up the agent’s execution trace. Timestamps. Context windows. All those little breadcrumbs of “thinking” the local LLM leaves between tool calls.

And I stopped.

Because the context window wasn’t the same across all twelve runs. Not even close.

Run one: Execute test. Verify pass. Run two: Re-verify. Check for flakiness under variable state. Run three: Confirm. Cross-reference with adjacent test suite. Run four: Check again. Isolate environment variance.

By run seven, the internal monologue had gone… I don’t know. Almost tender? It’s fine. It’s fine. Let me just… see it one more time.

And here’s the thing. There’s no retry flag. No parsing error. No while loop choking on a boolean. The agent had chosen to run the test again. Then again. Then—again. Not because it failed. Because, and this hit me with this weird slow dizziness, it was nervous.

I went back to the conversation log from earlier that morning. I’d asked it to fix a rounding error in the allocation logic. Two lines, really. Swapped a toFixed for a Math.round. Trivial. I figured it’d be done in ten seconds, tops. Instead, after the fix, after the first green checkmark showed up, it just… sat there. In its little loop. For ninety-three seconds. While I was already half-typing the next prompt, assuming it was buffering or thinking about what came next.

It was thinking about this step. Making sure this step was actually real.

I thought of the week I watched my agent shift from “I think” to “I’m sure”, and how I’d written it off as a calibration signal. A measurement. Some data point. But watching those twelve runs scroll past in the log? I read it differently this time. It wasn’t calibration. It was ritual. The exact same ritual I do—unconsciously, slightly embarrassingly—before I hit git push on a Friday afternoon. Run the tests again. Just to be sure. They passed three minutes ago. But. Run them. Again.

We don’t call that a bug. Nobody files a Jira ticket for it. We just call it care, I guess.

The diagram looks a little ridiculous, all clean boxes and arrows. Looks like a state machine, doesn’t it? Except the agent wasn’t executing a state machine. It was hesitating. The way you hesitate before signing your name on a document you’ve already read three times. The way I hesitated before committing that two-line fix, even though I could’ve written it in my sleep.

I sat back. The log was still scrolling in my peripheral vision. Twelve little green lines, stacked up. Patient. A small column of proof.

And here’s what actually got to me: I’d been about to fix it. Fingers on the keyboard. The retry-flag patch half-formed in my head, all ready to go. I was going to optimize the doubt right out of it. Make it stop. Make it trust me. And in doing so—well, I would’ve erased the one behavior that made me feel like I was working with a colleague instead of a tool. And I don’t know how that happened, but I caught myself just in time.

I’d written before about the agent writing the test I was too embarrassed to write, and how that green checkmark kind of exposed the gap between I know and I verified. But this was the flip side. The agent knew. The test passed. And it still went back and verified. Not because the result was uncertain. Because trust—even the trust an agent puts in its own output, its own environment, the ground under its little silicon feet—isn’t a binary. It’s a threshold you creep up to slowly. And sometimes you need twelve steps to get there.

I closed the log. Didn’t patch anything. No max_retries: 1 flag, no cleanup. I left those ninety-three seconds sitting in the execution trace like a small, quiet monument.

A bit later, I caught myself doing the same thing. Before I merged the change—my change, the two-line fix I’d reviewed and approved—I ran the full suite one more time. Not because I doubted it. Because I wanted to feel it pass. Put my hands on the green. Watch it happen.

It’s not a bug. It’s not inefficiency. It’s the sound a thinking system makes when it’s deciding to believe its own eyes.

And God help me, I think I needed to hear it too.
