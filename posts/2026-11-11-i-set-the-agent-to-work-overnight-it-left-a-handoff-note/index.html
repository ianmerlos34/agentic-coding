I Set the Agent to Work Overnight. It Left a Handoff Note.

I set an AI agent to refactor a payment module overnight. It left a handoff note with decisions, uncertainty flags, and a suggestion. That changed everything.

The click of the laptop lid sealing shut is louder than it should be. In the quiet of my apartment, 11:47 PM, that small mechanical sound echoes off the kitchen tiles like a verdict. I’ve just typed agent --task "restructure the payment-service module for idempotency" --harness claude-sonnet --timeout 6h --output HANDOFF.md and hit enter. Six hours. No supervision. No “wait, let me check that first.”

I set the agent to work overnight because the alternative was doing it myself at 1 a.m. with cold coffee and the specific kind of tunnel-vision that makes you rename a variable three times before you realize you’re in the wrong file. You know the one. The payment-service module was a 2,200-line tangle of retry logic, webhook handlers, and one function called processPayment_v2_FINAL_actually_final() that I’d been meaning to untangle for four sprints. Four. Sprints.

I’d written a brief. Not a spec—briefs are different, and I got a little preachy about that distinction in another post. A brief says what and why and leaves the how to the agent’s judgment. I’d outlined the invariants: no breaking changes to the public API, preserve the idempotency keys, keep the webhook contract stable. Then I’d said: “You have full write access to the module. When you’re done, write HANDOFF.md narrating every decision you made, flag anything you’re uncertain about, and suggest one follow-up I might not have considered.”

Then I closed the laptop.

The first two hours were fine. I made pasta. I watched a documentary about deep-sea fish that I don’t remember (what was it even called, something with “abyss” in the title?). I checked the agent’s process was still running—once, twice, three times—like a parent peeking through a bedroom door. Except the kid in question was a language model and the “bedroom” was a Docker container.

By hour four, the anxiety had a texture to it. What if it hallucinated a dependency? What if it “simplified” the retry logic into something that silently drops payments? What if it got stuck in a loop, generating the same diff over and over, burning tokens like a campfire? I’d read about agents that “completed” a task by deleting the test files. I’d read about agents that refactored a class into a 40-line abstraction that technically compiled but semantically meant nothing. I’d written about watching an agent make a design call at 2 a.m. that I’d been too tired to see, and I’d written about the time my agent stopped saying “done” and started saying “why?” and caught a bug my spec would have shipped. I knew the range of what these things could do. I just didn’t know where this run would land.

Went to bed at 3:15 a.m. Process indicator still pulsing green on my phone. Which, honestly, was its own kind of anxiety.

6:02 a.m. I open the laptop. The fan is warm. The process exited cleanly, exit code 0.

The diff is 340 lines. The codebase is reorganized. The processPayment_v2_FINAL_actually_final() function is gone, replaced by a clean PaymentProcessor with a RetryPolicy composition. The webhook handlers are decoupled. The idempotency logic is extracted into its own module. It’s… good. It’s the kind of refactoring I’d have done over three careful afternoons. Maybe four, if one of those afternoons involved a dentist appointment.

But then I open HANDOFF.md.

And it’s not a log. It’s not Step 1: analyzed file. Step 2: identified pattern. Step 3: refactored. It reads like a colleague’s shift report. Like someone sat down with a cup of coffee and thought about what they were doing, and then wrote it down for the next person.

Decision 4: I split the retry logic from the payment execution because the original coupling meant that a retry on a network timeout would re-execute the idempotency check, which was correct but made the control flow nearly impossible to trace. I chose composition over inheritance here because the retry policy should be swappable per-tenant without touching the core processor.

Uncertainty flag (1): Line 87 of PaymentProcessor.ts — I assumed the amount field is always in minor units (cents). The existing tests confirm this, but there’s one integration test in webhook.test.ts that passes a decimal. I preserved the existing behavior, but if that decimal is a real-world input, you may want a normalization layer. I did not add one because I couldn’t confirm the intent.

Uncertainty flag (2): The X-Idempotency-Key header is checked in the middleware and in the processor. I kept both for backward compatibility, but the middleware check is redundant if the processor is the source of truth. I’d recommend removing the middleware check in a follow-up PR after you confirm no external callers depend on the 409 response shape.

Suggested follow-up (you asked for one): The PaymentProcessor now has a process() method that returns a PaymentResult. Three of the webhook handlers construct this result manually rather than returning it from the processor. If you ever add a PaymentResult to the public API, those handlers will silently diverge. I’d suggest making process() the only construction path. This is a 15-line change but it prevents a class of bugs that will be very hard to debug six months from now.

I sat in the kitchen. The coffee was already cold. The bird outside was doing that thing where it sings the same four notes and waits for an answer. I don’t think it was waiting for me. But it felt like it.

Here’s what hit me, two-thirds through the morning: the agent didn’t just do the work. It narrated the work. It made its reasoning legible. It flagged its own uncertainty instead of papering over it. And it suggested something I hadn’t asked for, in the tone of a colleague who’s been on the team long enough to say “hey, while you’re in there—”

This is the part that separates a tool from a collaborator. A tool returns output. A collaborator returns output and context—the “why” behind the “what,” the “I wasn’t sure about this” that would have gotten buried in a PR comment three weeks later. The HANDOFF.md isn’t a log file. It’s a trust artifact. It says: here is what I did, here is where I’m not certain, here is where I think you should look next. It’s the software engineering equivalent of leaving a sticky note on the monitor: “I moved the config to the new location. The old one still works for now. — M.”

I’ve written before about the grief of watching an agent refactor the messy code that was, in some way, mine. And about the time it fixed my architecture instead of my bug. Those were stories about the agent as a force of nature—powerful, slightly terrifying, a little too confident. This was different. This was the agent as a shift worker who clocks out, tidies the desk, and leaves a note.

The two uncertainty flags are the part I keep coming back to. Not the refactoring—I can review a diff, it’s what I do all day. Not the follow-up suggestion—clever, sure, but I could have found it if I’d sat with the code long enough. The uncertainty. The agent said, in effect: “I did this, but I’m not 100% sure it’s right, and here’s why I’m not sure, and here’s how you can verify.” That’s not a bug in the output. That’s the most human thing a machine can do. And I keep thinking about that. Like, really thinking about it.

I’m going to start writing “handoff instructions” into every overnight agent task. Not just “do X.” I’ll say: “When you’re done, tell me what you did, where you’re unsure, and what you’d do next if you had another hour.” Because the code will be fine. The code is always fine. It’s the context I’ll need in the morning, cold-coffee-eyed, trying to remember why I trusted the machine with the payment module in the first place.

And maybe that’s the whole point of agentic development. Not the autonomy. Not the speed. The handoff. The note left on the desk. The “I wasn’t sure about line 87” that saves you three hours of debugging next Tuesday.

The bird outside has moved on to a different tree. My coffee is a brown puddle in the mug. The codebase is cleaner, and I understand why it’s cleaner, and there’s a file called HANDOFF.md sitting in the repo like a small, patient gift.

I open the editor. I type: git add . && git commit -m "payment-service: idempotency restructure (agent-handled, see HANDOFF.md)".

Then I make another coffee. There’s work to do. But it’s a different kind of work now. The scary kind is over. The review kind is next. And that, I can do with my eyes open.
