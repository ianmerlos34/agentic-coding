The Agent Wrote the Test I Was Too Embarrassed to Write

My AI agent wrote a test I’d been avoiding for six weeks. It passed. And that green checkmark exposed the gap between ‘I know’ and ‘I verified’ in my own code.

The green checkmark blinked at me like a small, indifferent sun.

tests/payment/test_fallback_routing.py::test_stale_token_triggers_retry PASSED

I read it three times. Not because I couldn’t parse the assertion. Because my brain kept insisting that test shouldn’t exist. And then, worse: that it shouldn’t have passed.

It was a Tuesday. 9:47 a.m. I’d been staring at my screen for about forty minutes, running coffee through my hands in slow circles, trying to figure out why my agent had added a test file I’d never asked for, never reviewed, and—God help me—needed.

The Fallback I “Knew” Never Fired

Six weeks earlier, I’d shipped the payment module. Clean. Elegant. A thin orchestration layer over three providers, a circuit breaker, a retry queue. The kind of code you write at 11 p.m. on a Friday when the architecture finally clicks and your fingers move faster than your doubt.

Except there was a seam. A fallback path. When the primary provider returns a 408 with a stale token, the code falls through to a secondary route that re-authenticates via a legacy OAuth endpoint. I’d written it in one sitting, tested the happy path, tested the primary error, and moved on.

The fallback? I “knew” it never fired. I’d watched the logs for three sprints. Zero hits. The primary provider’s token rotation was bulletproof. I was sure.

“Bulletproof” and “sure”—yeah, those are the two most expensive words in a developer’s vocabulary. I should have known. I’d written about it before, in that post where I sat still for an hour after a 40-second fix and realized my identity was tangled up in knowing things without proving them (It Wrote the Fix in 40 Seconds. I Sat Still for an Hour.). But knowing that intellectually and feeling the gap in your own code? Those are different animals entirely.

What the Agent Actually Did

Here’s the thing that still makes my chest tight: it wasn’t dramatic. No resignation letter in markdown, no failing test with a passive-aggressive message pinned to the repo. (My Agent Wrote a Failing Test Just to Talk to Me was that kind of moment. This was quieter.)

I’d given it a routine task on Monday: “Add the new SEPA transfer method to the provider router. Match the existing pattern.” Standard. Boring. The kind of thing you do between meetings. You know, the stuff that feels like filing paperwork but for code.

It did that. And then—because I’d onboarded it properly, because I’d spent three days feeding it the decision narratives and the why behind each provider choice (I Onboarded My Agent Like a New Dev. It Took 3 Days)—it noticed something. The SEPA path shared a token-refresh dependency with the primary provider. And the fallback re-auth endpoint had no test coverage. Not a single assertion. Not a @pytest.mark.integration tag. Nothing.

So it wrote the test. Mocked the 408. Simulated the stale token. Exercised the fallback. And the fallback worked.

That’s the part that undid me. I’d assumed it was broken. I’d assumed it was dead code, a ghost branch I’d written in a panic and never cleaned up. And I’d been proud of shipping without testing it, because testing it would have meant admitting I didn’t actually understand what it did. Which, yeah. That’s… that’s not a great place to be.

The Embarrassment Has a Shape

It’s not the kind of embarrassment that shows up in a code review. “Hey, did you test the fallback?” No. It’s the private, 2 a.m. kind. The I wrote this and I don’t fully trust it and I’d rather it never fire than admit I’m not sure it works kind. You know the one.

My agent doesn’t have that ego. It doesn’t have the Friday-night 11 p.m. momentum that made me think “obviously this works, why would I test it.” It sees a branch. It sees a missing test. It writes the test. It runs it. It passes. It moves on.

No judgment. No “you were overthinking it” commit message, though honestly, that would’ve been fair too (My Agent Committed Code With a Note: ‘You Were Overthinking’). Just: here’s the gap, here’s the fill, it’s green, next.

What I Changed

I went back through the entire payment module. Every if/else. Every try/except with a pass in the body. Every “I’ll add this test when we have a flaky incident.” I wrote them. Twelve tests. Two of them failed on first run—not the fallback, but a race condition in the circuit breaker reset that I’d hand-waved in a comment three months ago.

The fallback was fine. It had always been fine. My trust in it was the broken thing.

def test_stale_token_triggers_retry(self, mock_primary_408):
    """Fallback re-auth path fires when primary returns stale token."""
    result = self.router.process_payment(
        provider="stripe",
        token=self._expired_token(),
    )
    assert result.status == PaymentStatus.COMPLETED
    assert self.legacy_oauth.call_count == 1
    assert self.legacy_oauth.call_args.kwargs["grant_type"] == "refresh_token"

Forty-two lines. I’d read that function eleven times in the last six weeks. And not once did I think: what if the 408 actually comes? What does the code do? Does it do what I think it does? I don’t even know how to explain that. I just… didn’t.

The Green Checkmark, Revisited

I keep the test. I keep the name. I don’t rename it to something cleaner or more “production-ready.” It’s called test_fallback_routing.py and it’s slightly over-commented and one of my assertions is more verbose than it needs to be.

It’s the most honest file in the repo. And I can’t delete it. Which is the point, I think.

Because here’s what hits you two days later, when you’re writing the next module and you catch yourself thinking I’ll test that later:

The agent will write the test you’re too proud to write. And it will pass. And the green checkmark will be the most embarrassing thing you’ve seen all week. Not because the code was broken. Because you were the broken part. The part that substitutes “I know” for “I verified.”

My agent doesn’t know me. It doesn’t know what I’m embarrassed about. It just sees a branch with no coverage, and it does the only reasonable thing.

It writes the test.

It passes.

And I sit there, holding my lukewarm coffee, feeling forty-seven years old and slightly less proud.

Which, I’m learning, is the whole point.

So. The next time your agent adds a test you didn’t ask for, don’t close the tab. Don’t think oh, that’s probably fine, I’ll review it tomorrow. Read it. Run it. Let the green checkmark be a small, quiet mirror.

Because the test it wrote isn’t testing my code.

It’s testing my confidence in my code. And that’s the test I was never going to write on my own.
